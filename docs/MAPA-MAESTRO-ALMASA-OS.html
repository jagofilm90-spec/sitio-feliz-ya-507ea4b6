02 Los 10 Procesos Operativos

Flujos end-to-end desde el trigger hasta la conclusión. Cada proceso toca múltiples tablas y roles.

1. Alta de Empleado

Rol: Admin/Secretaria · Pantalla: /empleados → Nuevo · ~10 min
Admin → "Nuevo empleado"
Paso 1: Datos básicos
nombre, apellidos, puesto, fecha_ingreso, teléfono, email
Paso 2: Laboral
sueldo_bruto, periodo_pago, premio_asistencia, comisión, NSS, RFC, CURP, días laborales
Paso 3: Documentos
INE, CURP, comprobante, acta, CSF, licencia ⚠️ Upload pendiente
Paso 4: Resumen → Submit
→ INSERT empleados (16 campos) · activo=true · user_id=null
Post-alta (EmpleadoFicha)
Firma contrato (PDF+email) · Expediente digital · Dar acceso sistema → create-user Edge Function → user_roles · Mapeo ZKTeco · Vacaciones · Actas
→ TRIGGER auto_link_user_employee si email coincide
Empleado activo con acceso

2. Alta de Producto

Rol: Admin/Secretaria · Pantalla: /productos → Dialog · ~3 min

Dialog inline en Productos.tsx → campos: código, nombre, marca, categoría, unidad, precio_venta, precio_por_kilo, peso_kg, descuento_máximo, aplica_iva/ieps, stock_mínimo, codigo_sat, unidad_sat → INSERT productos. Trigger: on_producto_precio_change registra historial automático.

3. Alta de Cliente

2 flujos paralelos — datos distintos por propósito
Admin (fiscal)
/clientes/nuevo · Page completa
CSF parser · RFC validado · dirección fiscal · régimen · CFDI · vendedor asignado · crédito · N sucursales
→ clientes + cliente_sucursales · RPC generar_codigo_cliente
Vendedor (operativo)
Sheet lateral desde VendedorPanel
Nombre + dirección desglosada + CP lookup + GPS Google Maps + horarios + días sin entrega + teléfonos/correos/contactos
→ clientes + sucursal "Principal" + correos + teléfonos + contactos

4. Compra a Proveedor

Rol: Admin/Secretaria · Pantalla: /compras → Wizard 4 pasos · ~15 min
Crear Orden de Compra
Wizard: proveedor → productos → entregas → confirmar
→ INSERT ordenes_compra + ordenes_compra_detalles · RPC generar_folio_orden_compra · Email a proveedor
Recepción en almacén
Verificar cantidades · diferencias (roto/no llegó/rechazado) · evidencia fotográfica · firma digital
→ INSERT inventario_lotes · UPDATE ordenes_compra status · Email confirmación
Conciliación factura proveedor
→ RPC conciliar_factura_proveedor · UPDATE costos productos · Recalcula costo_promedio_ponderado
Inventario actualizado + costos sincronizados

5. Captura de Pedido

3 flujos: admin (dialog) · vendedor (wizard 4 pasos + offline) · cliente (page portal)

→ RPC generar_folio_pedido (PED-YYYYMMDD-NNN) · INSERT pedidos + pedidos_detalles · calcularTotalesPedido (shared) · alertas_precio JSONB · status=pendiente (admin/vendedor) o por_autorizar (cliente) · Notificaciones push a secretaria · Email interno + cliente · PDF nota interna + confirmación · Autosave borrador DB + IndexedDB offline

6. Carga de Ruta (Almacén)

Rol: Almacén/Gerente · Pantalla: /almacen-tablet → Rutas · ~20-40 min por ruta

CargaRutaInlineFlow (3 pasos: selección chofer/vehículo → escaneo QR → hoja interactiva) · useCargaOperations: 8 funciones atómicas · RPC decrementar_lote por producto · Resync totales pedido · status=en_ruta · PDF hoja de carga

7. Entrega (Chofer)

Rol: Chofer · Pantalla: /chofer · Todo el día

GPS tracking web + nativo (Capacitor background) cada 30s → chofer_ubicaciones · RegistrarEntregaSheet: status entregado/parcial/rechazado · Firma digital canvas · 7 motivos de rechazo · Auto-completar ruta cuando todas las entregas están hechas

8. Facturación

⚠️ CAMBIO ESTRATÉGICO (24 abril 2026)

Este proceso está en transición. Objetivo: usar Aspel como sistema principal de facturación. Integración ALMASA-OS ↔ Aspel por definir. El código actual de Facturama se mantiene por ahora pero está marcado como legacy.

Rol: Admin/Secretaria/Contadora · Pantalla: /facturas o SecretariaFacturacionTab

Flujo actual (Facturama — legacy): GenerarFacturaDialog (desde pedido) o NuevaFacturaDirectaDialog (sin pedido) · Edge Function timbrar-cfdi → Facturama API → CFDI UUID + XML + PDF URLs · Cancelación con motivos SAT (01-04) · Remisión/Nota de venta imprimible · Envío por email

Plan futuro (Aspel):

  • Aspel será el sistema de facturación principal
  • Los pedidos/remisiones se exportarán a Aspel (método por definir)
  • Aspel timbra y devuelve CFDI
  • Facturama queda como respaldo o se elimina después

9. Cobranza

Rol: Vendedor (registra) → Secretaria (valida) · ~2 min por cobro

VendedorCobranzaTab → RegistrarCobroPedidoDialog (4 formas: efectivo/depósito/transferencia/cheque) · RPC registrar_cobro_pedido · pagos_cliente status=pendiente → Secretaria valida → status=validado · Trigger actualizar_saldo_cliente_pago recalcula saldo

10. Asistencia

Automático: ZKTeco sync · Manual: Admin/Secretaria · Pantalla: /asistencia 5 tabs

Python script lee ZKTeco 192.168.1.126/127 cada 60s → INSERT asistencia · Retardo si > 8:30 AM · Premio binario: 1 falta = $0, 2+ retardos = $0 · Reportes: semanal, quincenal, mensual · Mapeo admin ZK → empleado · Vacaciones masivas

07 Ciclo de Vida del Pedido

El pedido es el objeto central del sistema. Atraviesa 7 estados y toca 12+ tablas.

VENDEDOR captura pedido (wizard 4 pasos + offline)
RPC generar_folio_pedido → PED-YYYYMMDD-NNN
→ INSERT pedidos (status=pendiente) + pedidos_detalles · alertas_precio JSONB
¿Tiene alerta de precio?
bajo_piso o error_dedo → Push notification a admin · Admin/Secretaria revisa en AutorizacionRapidaSheet
ALMACÉN selecciona para carga
CargaRutaInlineFlow: chofer + vehículo + escaneo QR + hoja interactiva
→ RPC decrementar_lote × N productos · carga_productos · resyncPedidoTotals
status = en_ruta
Pedido asignado a ruta con chofer/vehículo · PDF hoja de carga impreso
→ UPDATE pedidos status · UPDATE rutas status=cargada · Notif vendedor
CHOFER entrega
GPS tracking 30s · Firma digital canvas · status: entregado/parcial/rechazado
→ UPDATE entregas · chofer_ubicaciones · RegistrarEntregaSheet
SECRETARIA decide: ¿facturar o remisión?
Si factura → exportar a Aspel (futuro) / Facturama (actual, legacy)
Si no → queda como nota de remisión, va a factura global mensual
status = entregado
Vendedor/Admin registra cobro · 4 formas de pago
→ RPC registrar_cobro_pedido · pagos_cliente status=pendiente
SECRETARIA valida pago
→ pagos_cliente status=validado · TRIGGER actualizar_saldo_cliente_pago
PEDIDO CERRADO — ciclo completo

Estados del pedido

borrador → por_autorizar → pendiente → en_ruta → entregado → por_cobrar | rechazado | cancelado
