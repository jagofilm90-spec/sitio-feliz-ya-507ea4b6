Este documento muestra lado a lado TODAS las funciones de ALMASA-OS que tienen implementación distinta para diferentes roles. El objetivo es ver las diferencias con los ojos — no juzgarlas todavía.

Divergencia legítima = el rol tiene necesidades genuinamente distintas (ej: vendedor en campo vs admin en oficina). Divergencia cuestionable = mismo propósito, distinto look sin razón clara.

5. Listar Clientes

3 implementaciones · Admin: tabla jerárquica + mapa · Secretaria: tabla simple · Vendedor: cards por región

  • 🟢 Admin tiene vista mapa + detección de grupos + import Aspel. Vendedor tiene cards por región geográfica con GPS status.
  • 🟢 Vendedor filtra por región (Valle México, Toluca, Morelos). Admin filtra por vendedor/zona/crédito.
  • 🟡 Secretaria es tabla simple con filtro vendedor — podría reusar Clientes.tsx con permisos.

6. Lista de Precios

3 implementaciones · 1,534 líneas totales · Hooks shared ya extraídos (M04.5B.2)

  • 🟢 Admin: 11 cols + simulador + bulk update + Excel. Vendedor: read-only + comparar último precio cliente. Secretaria: edición + calculadora margen.
  • 🟢 3 hooks shared (useListaPrecios, usePrecioEditor, usePrecioHistorial) centralizan lógica. UI shells son genuinamente distintos.
  • 🟢 Ya se extrajeron PromocionBadge + ImpuestoBadges + ListaPreciosPdfButton como shared. Conclusión: divergencia es legítima (docs/lecciones/lista-precios-consolidacion.md).

7. Ver Inventario

3 implementaciones · Admin: 4 tabs CRUD · Secretaria: 3 tabs read-only · Almacén: ajuste stock

  • 🟢 Admin tiene CRUD completo (nuevo movimiento, editar lote). Almacén tiene "Ajustar stock" con dialog (canAdjust via usePermissions).
  • 🟢 Secretaria es read-only monitoring con alerta stock bajo.

8. Detalle de Pedido

2 implementaciones · Admin: Dialog con edición precios · Vendedor: Dialog read-only + descuentos

  • 🟢 Admin puede editar precio unitario inline (canEditPrice via usePermissions). Vendedor solo ve.
  • 🟢 Vendedor ve alerta de descuento solicitado con grid lista/máx/solicitado/diferencia. Admin no lo necesita.

9. Ver/Editar Cliente

2 implementaciones · Admin: Page multi-tab · Vendedor: Sheet lateral

  • 🟢 Admin tiene page completa con 8+ tabs (pedidos, facturas, pagos, contactos, programación, cortesías, excepciones, usuarios).
  • 🟢 Vendedor tiene sheet compacto con tabs básicos (info, pedidos, facturas, pagos, historial precios).

Conclusión

La mayoría de las divergencias son legítimas — cada rol tiene necesidades genuinamente distintas. Las 6 cuestionables son áreas donde podría haber consolidación parcial (como se hizo con Lista de Precios). Cero divergencias son problemáticas (bugs o inconsistencias graves).

Top 3 oportunidades de consolidación (sin urgencia):

  1. SecretariaPedidosTab → evaluar si puede reusar Pedidos.tsx con roles (pero secretaria=desktop only, admin tiene cotizaciones/analytics que secretaria no usa)
  2. SecretariaClientesTab → evaluar si puede reusar Clientes.tsx con filtro vendedor
  3. Nuevo Cliente: unificar cómo se guarda la dirección (texto libre vs desglosada) sin fusionar los formularios
